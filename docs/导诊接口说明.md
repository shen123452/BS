# 问诊与导诊接口说明

更新日期：2026-10-24。本文记录已实现接口；开发依据已切换为[完整版](../完整版/README.md)（V1.0，逐阶段实施），验证边界见[开发进度](开发进度.md)。

## 通用约定

统一 `/api` 前缀，认证为 `Authorization: Bearer <token>`。普通响应为 `code/message/data/traceId`，ID 使用字符串传输；患者身份从登录账号取得，客户端不能指定 patientId。患者只能操作本人资源，管理员接口仅 ADMIN 可用。

## 患者流程

AI Key 由管理员在“AI 配置”页保存到 MySQL：`GET /admin/ai/config` 读取配置状态，`PUT /admin/ai/api-key` 接受 `{apiKey}` 保存。均仅 ADMIN 可用，响应不含密钥；环境变量仅首次无数据库记录时导入。保存不调用模型，后续问诊/检索/导诊请求读取数据库配置。

| 方法 | 路径 | 功能 |
|---|---|---|
| POST/GET | `/patient/consultations` | 创建/分页读取本人会话 |
| GET | `/patient/consultations/{id}` | 读取会话、摘要版本与确认状态 |
| GET | `/patient/consultations/{id}/messages` | 恢复本人消息 |
| DELETE | `/patient/consultations/{id}` | 逻辑删除本人非活动会话，保留消息、导诊、预约与病历 |
| GET | `/patient/consultations/{id}/triage-runs` | 恢复该会话的导诊历史，page/pageSize，最新任务在前 |
| POST | `/patient/consultations/{id}/messages` | 发送消息，SSE 返回 `meta/delta/done/error` |
| POST | `/patient/consultations/{id}/cancel` | 按 operationId 取消当前流式操作 |
| PUT | `/patient/consultations/{id}/summary` | 保存或确认结构化摘要 |
| POST | `/patient/triage-runs` | 创建导诊任务，HTTP 202 |
| GET | `/patient/triage-runs/{id}` | 轮询状态、公开步骤及结果关联 |
| POST | `/patient/triage-runs/{id}/cancel` | 取消本人任务 |
| GET | `/patient/triage-runs/{id}/events` | 事件订阅：cursor 之后的公开事件按序补齐，返回 latestSeq 与运行状态；按 seq 去重，断线重连不丢事件不发新任务 |
| GET | `/patient/triage-results/{id}` | 读取推荐、证据、场次快照及能否预约 |

摘要请求包含 `summary`、`expectedSummaryVersion`、`confirm`。摘要包括主诉、持续时间、严重程度、伴随/否定症状及五项危险信号；每项危险信号只能为 YES、NO、UNKNOWN。须先核对并确认，不能把未知当作否定。继续发送新消息会更新摘要版本并使旧推荐失效。

创建任务请求包含 `sessionId`、`summaryVersion`、`clientRequestId`。同一请求号绑定会话和摘要版本，重试复用请求号；内容不一致返回冲突。创建后前端每两秒轮询，终态停止。任务仅提供公开阶段，不返回模型隐藏推理。

任务状态包括 QUEUED、RUNNING、SUCCEEDED、DEGRADED、FAILED、CANCELLED。超时按失败终止，并记录公开错误说明。明确急症不调用模型生成普通门诊推荐；证据不足可降级，信息不足要求补充。

会话详情返回 `activeOperationId/activeOperationType`；CHAT 可通过问诊取消接口停止，TRIAGE 须通过导诊取消接口停止，不能相互释放活动锁。活动任务存在时删除返回 409/SESSION_BUSY；删除后会话详情、消息及历史列表返回 404。已存运行/结果仍可按本人 ID 查阅，删除会话的结果不能用于新关联预约，已有关联预约不被级联删除。

历史列表返回原 run ID、创建时间、公开步骤和 result ID（有结果时），读取和刷新不创建新任务或调用模型。旧摘要、旧最新结果、过期结果及删除会话的结果均由服务端重新核验预约资格。

## 预约关联

普通预约可不带 `triageResultId`。由结果页预约时携带字符串结果 ID，后端重新检查本人归属、有效期限、摘要确认/版本、最新结果、风险和推荐科室集合。跨出推荐/备选科室时前端清除关联，不能绕过校验。场次余号以预约提交时的数据库条件更新为准，结果中的场次快照不保证保留号源。

## 数据库工具注册中心与预算

工具池来自 MySQL `mcp_tool` 表的启用状态（完整版阶段一），不再是代码固定三工具。基线六工具：

| 工具编码 | 数据来源与限制 |
|---|---|
| `medical_knowledge_retrieve` | 当前向量空间内已启用 READY 文档；topK 为 1～5，引用须为本轮实际命中片段 |
| `patient_profile_read` | 运行上下文注入的本人档案（性别/年龄/慢病/过敏），参数不接受患者身份字段 |
| `visit_history_read` | 本人最近三次已完成就诊的科室与诊断摘要 |
| `symptom_tag_search` | 症状标签及科室权重，仅提示数据；危急判定以系统强制规则为准 |
| `department_search` | 实际启用科室目录 |
| `doctor_schedule_search` | 实际七日可预约日期范围，按有效科室查询真实排班 |

工具池快照在任务创建时固定并写入 `agent_run.tool_names`；运行中工具被停用向模型返回 `TOOL_DISABLED`，不执行业务查询，管理员修改从下一次新运行生效。每次真实执行写入 `mcp_tool_call_log`（来源 AGENT/ADMIN_TEST、脱敏入参、耗时、错误码）。

最多 6 轮模型调用、12 次工具调用、60 秒总时限（完整版放宽自缩减版 4 轮/6 次）。工具参数、工具名和调用 ID 均校验；知识工具最多 30 秒，SQL 工具与最终校验最多 3 秒，且不能超过剩余总时限。取消、超时和摘要变化后，晚回调不得发布结果。

Prompt 亦为数据库模板：`prompt_template` 草稿发布为不可变 `prompt_revision`；运行固定创建时快照并记录 `prompt_revision_id`/`prompt_content`，发布或回滚从下一次新运行生效，代码内置兜底保证无数据库修订时系统可用。

## 知识库维护

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | `/admin/knowledge/status` | AVAILABLE/UNAVAILABLE/MAINTENANCE、当前空间、候选数及重建总数/就绪数/失败数 |
| POST | `/admin/knowledge/rebuild` | HTTP 202，全量按当前模型重建，或重新开始失败/换空间后的维护 |
| POST | `/admin/knowledge/documents/{id}/rebuild` | HTTP 202，单独重建已停用且 READY/FAILED 的资料 |
| POST | `/admin/knowledge/documents/{id}/retry` | FAILED 重试；维护期只允许当前空间的 REBUILD 目标 |

重建需要已配置 AI，有活动导诊返回 409/AGENT_ACTIVE，有活动资料处理返回 409/KNOWLEDGE_BUSY。在写向量前以一个 MySQL 事务将全部目标持久化为 REBUILD/QUEUED 和统一目标空间，随后单个受限后台任务依次处理，避免队列部分接受。全量重建保留每份资料的启用选择；单份停用资料重建后仍停用。正文与片段 ID 复用，不改变历史引用。

维护与新导诊接收共用单机读写锁，覆盖运行记录创建事务提交边界。维护期上传、启停、检索及新普通导诊返回 409/KNOWLEDGE_MAINTENANCE；明确危险信号仍执行无需检索的急症规则，普通预约不受影响。已有请求号可恢复原任务。

仅全部目标 READY、目标空间一致、逐片段向量 ID/维度/有效性校验通过后，才清除持久化维护标记；部分失败、队列拒绝、超时、重启不会提前开放。重启将中断目标记为 FAILED，仍保持维护，可重试失败资料；模型空间已改变时须重新开始全量重建。
