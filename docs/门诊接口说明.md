# 门诊接口说明

当前实现：管理员医生维护与排班、患者普通预约/取消、医生接诊和七段病历。统一`/api`前缀和`Authorization: Bearer token`，角色和归属来自登录身份。ID响应为字符串，错误信封沿用code/message/data/traceId。

## 管理员维护医生

`PUT /api/admin/doctors/{id}`：

```json
{
  "departmentId": "实际科室ID",
  "name": "医生姓名",
  "title": "主治医师",
  "specialty": "专长说明",
  "status": "ENABLED"
}
```

status为ENABLED或DISABLED。转科前须处理未来WAITING/IN_PROGRESS预约、关闭未来OPEN排班，否则409/DOCTOR_IN_USE。保留历史场次和预约科室快照，不通过转科改写旧记录。医生或其账号停用后不再接受新预约。

## 管理员排班

`POST /api/admin/schedules`新建；`PUT /api/admin/schedules/{id}`更新：

```json
{
  "doctorId": "实际医生ID",
  "visitDate": "2026-10-14",
  "timeSlot": "AM",
  "totalCount": 20,
  "fee": 20.00,
  "status": "OPEN"
}
```

示例日期应换成实际当前/未来日期。departmentId从医生取；remainingCount由后端计算，请求不能设置。totalCount为1..100000，fee非负且最多两位小数，status为OPEN/CLOSED。status省略时新建默认OPEN、更新保留原状态。

时间统一为Asia/Shanghai。AM开始08:00，PM开始14:00；bookingDeadline可选，格式如`2026-10-14T07:30:00`，默认开始前30分钟且不得晚于开始时间。OPEN须未截止；新建/变更身份不能指向过去日期。同医生、日期、时段唯一，重复409/DUPLICATE_SCHEDULE。

已有任何历史预约时不能改doctorId、departmentId、visitDate或timeSlot。改变totalCount在锁定场次后按`已占用=旧totalCount-旧remainingCount`重算：例如原10号余2号，已占8；改成7拒绝，改成12时余4号。改费用不改已有预约费用快照。

`POST /api/admin/schedules/{id}/close`：关联WAITING/IN_PROGRESS预约时409/SCHEDULE_IN_USE，否则关闭。无物理删除历史场次接口。

`GET /api/admin/schedules`支持departmentId、doctorId、status、startDate、endDate、page、pageSize；默认今天起七天，单次日期范围最多93天。

## 场次查询

`GET /api/schedules`：已登录用户可用，支持departmentId、doctorId、date、page、pageSize。只列今天到今天+6天内、医生/科室/账号启用、未截止且余号大于0的OPEN场次。指定date须在同一七天范围内。

返回分页信封items/total/page/pageSize，每项包含id、doctorId、departmentId、doctorName、departmentName、visitDate、timeSlot、bookingDeadline、totalCount、remainingCount、fee、status和bookable。

`GET /api/schedules/{id}`：返回上述七天内启用场次的实时信息。满号或已截止时可以返回bookable=false；已关闭、身份停用或七天范围外返回404。确认后提交仍由后端重新检查余号和截止。

`GET /api/doctor/schedules`：仅医生本人，startDate/endDate/page/pageSize，不接受另一个doctorId。

## 患者预约与取消

`POST /api/patient/registrations`：

```json
{
  "scheduleId": "实际排班ID",
  "clientRequestId": "前端为本次确认生成的唯一请求号",
  "symptomDescription": "患者确认的就诊说明"
}
```

clientRequestId需为1..64位ASCII字母、数字、点、下划线、冒号或短横线。一次确认持续复用同请求号直到明确结果；取消后重新预约使用新请求号。symptomDescription可省略，最多10000字符。患者姓名须先在本人档案完善；否则422/PROFILE_INCOMPLETE。

新建201，重复同请求200返回原预约，不再次扣号，即使原预约已取消。相同clientRequestId但scheduleId、triageResultId或规范化症状不同，409/REQUEST_ID_CONFLICT。同患者同日同时段最多一个WAITING/IN_PROGRESS，冲突409/DUPLICATE_ACTIVE_SLOT。余号不足409/SCHEDULE_FULL，已截止409/BOOKING_EXPIRED，已关闭409/SCHEDULE_CLOSED。

可选triageResultId已实现归属和有效性校验：须本人、VALID/ROUTINE、未过期、会话未删、摘要确认且版本一致、最新结果匹配、所选科室在主/备选推荐集合中。业务导诊结果生成尚未实现，当前普通预约无需该字段。更换推荐集合外科室时移除关联，不允许伪造结果ID。

预约响应保存挂号号、患者/医生/科室名称、费用、日期/时段快照；之后基础信息修改不改历史。没有支付。

`GET /api/patient/registrations`本人分页，支持status/page/pageSize；`GET /api/patient/registrations/{id}`本人详情，其他患者ID返回404。

`POST /api/patient/registrations/{id}/cancel`可不带正文，或传`{"reason":"取消原因"}`，原因最多255字符。仅本人且预约截止前WAITING可取消并返号一次；重复取消返回原CANCELLED记录，不重复返号。IN_PROGRESS/COMPLETED不能取消。

## 医生接诊与病历

`GET /api/doctor/registrations`支持date/status/page/pageSize，默认当天，仅本人名下。`GET /api/doctor/registrations/{id}`返回本人名下预约及其患者档案；其他医生ID返回404。

`POST /api/doctor/registrations/{id}/start`仅可开始当天WAITING预约，同事务创建version=0的DRAFT病历。重复开始不创建第二份草稿；已取消拒绝。取消和接诊竞争只允许一个状态路径。

`GET /api/doctor/registrations/{id}/medical-record`读草稿或已提交正文。`PUT`同路径保存草稿：

```json
{
  "version": 0,
  "chiefComplaint": "主诉",
  "presentIllness": "现病史",
  "pastHistory": "既往史",
  "physicalExam": "体格检查",
  "auxiliaryExam": "辅助检查",
  "preliminaryDiagnosis": "初步诊断",
  "treatmentPlan": "处理计划"
}
```

草稿允许未完成字段，每段最多10000字符；保存按doctorId/DRAFT/version条件更新，成功version+1。两个窗口同version仅一个成功，另一个409/RECORD_VERSION_CONFLICT。

`POST /api/doctor/registrations/{id}/complete`传当前草稿版本，如`{"version":1}`。七段须全部非空；否则422/RECORD_INCOMPLETE。病历SUBMITTED与预约COMPLETED在同一MySQL事务提交，任一失败一起回滚。提交后不允许PUT改正文，重复complete返回原提交记录。

`GET /api/patient/registrations/{id}/medical-record`仅本人SUBMITTED可读。草稿或他人病历返回404；管理员没有通用病历读取/编辑接口。

## 验证范围

真实MySQL测试覆盖七天场次、排班唯一、请求重放、历史快照、取消返号、接诊和病历归属、并发抢号/重复请求/同患者时段冲突、取消接诊竞态、病历并发版本、注入失败回滚及导诊关联约束。模型和导诊关联故障数据为测试构造，普通门诊验证不等同于业务AI已实现。

前端已在 `hospital-web` 创建，管理员、医生、患者的普通门诊页面对接本文接口。后端在IDEA正常启动，前端运行 `npm run dev` 后通过5173访问；数据库无需重建或重复运行建表脚本。请求正文必须仅包含接口定义字段，禁止将列表展示ID或状态等多余字段整体回传。
