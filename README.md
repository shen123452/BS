# 医院智能导诊系统

毕业设计题目：**基于检索增强生成与智能体的医院智能导诊系统设计与实现**。

开发依据已切换为[完整版](完整版/README.md)（V1.0，2026-10-08），按阶段逐步从缩减版实现升级；网站角色固定为管理员、医生、患者。更新日期：2026-10-24。

## 技术与数据库

| 部分 | 技术与职责 |
|---|---|
| 前端 | Vue 3、Vite、Element Plus、Vue Router、Axios，蓝白管理界面 |
| 后端 | Java 21、Spring Boot 3.5.13、MyBatis-Plus 3.5.15、Spring Security、JWT、LangChain4j 1.0.1 |
| 本地 MySQL 5.7 | `127.0.0.1:3306/hospital_triage`，24 张表，保存账号、门诊业务、问诊、导诊、知识资料正文、AI 凭据、模型配置修订、工具注册、Prompt 修订与症状标签 |
| Docker PostgreSQL / pgvector | `127.0.0.1:5433/hospital_triage_vector`，保存知识向量，使用独立 JdbcTemplate 与事务管理器 |
| 模型服务 | 阿里云百炼，`qwen-plus`、`text-embedding-v4`，向量维度 1024 |

数据库连接账号与网站三角色分别配置。两个数据库无跨库外键，不使用分布式事务。

## 当前开发成果

- 管理员：用户启停、科室/医生维护、排班管理、症状标签维护、知识资料上传/启停/失败重试/检索、维护重建与单份停用资料重建、AI 配置、AI 模型配置修订（聊天/向量分离、测试/激活）、Prompt 模板草稿/发布/回滚、工具中心（数据库登记/启停/测试/调用日志）、导诊运行记录和基础统计。
- 医生：本人排班、名下候诊列表、患者档案、当天开始接诊、七段病历草稿保存及提交。
- 患者：注册登录、个人档案、七日号源查询、预约与取消、就诊与已提交病历、流式 AI 问诊、会话逻辑删除、症状确认、导诊运行/历史恢复与结果、关联预约。
- 导诊 Agent：工具池来自数据库启用状态（基线六只读工具），最多 6 轮、12 次工具调用、总时限 60 秒；运行固定创建时的 Prompt 修订与工具快照，支持轮询、取消、引用校验、急症拦截、有限证据降级和过期结果失效。

系统开发进度：缩减版范围（三端普通门诊、SSE 问诊、知识库、受控导诊 Agent、监控统计）约 75%～80%（工程估算）；完整版按阶段推进，阶段一（工具注册中心/Prompt 修订/症状标签）与阶段二（AI 模型配置修订）已实现并通过验证并推送 GitHub。完整真实模型联调、空间切换/故障专项、事件回放、运营看板、医生反馈与性能实验仍待完成。具体证据见[开发进度](docs/开发进度.md)。

## 本地启动

1. 启动本地 MySQL 5.7 和 Docker 中的 `hospital-triage-pg`。新环境先按[SQL 说明](缩减版/sql/README.md)初始化两个独立数据库；已有本地数据库不要重复建表。
2. 在 IDEA 打开 `hospital-server/pom.xml`，选择 JDK 21。
3. 在 `HospitalApplication` 的本机运行配置填写 `MYSQL_PASSWORD`、`VECTOR_DB_PASSWORD`、`JWT_SECRET`。AI Key 由管理员在“AI 配置”页保存到 MySQL；首次没有数据库记录时才可用 `DASHSCOPE_API_KEY` 导入。变量说明见[后端 README](hospital-server/README.md)。
4. 运行 `com.shen.hospital.HospitalApplication`，默认监听 `http://127.0.0.1:8082`。首次空库须显式配置管理员初始化；本机已有管理员，无需重新创建。
5. 在 `hospital-web` 首次运行 `npm install`，之后运行 `npm run dev`，或使用 IDEA 的 npm `dev` 任务。
6. 打开 **http://127.0.0.1:5173**，使用本机已设置的账号登录。患者可公开注册，医生由管理员创建。

数据库密码和 JWT 密钥由本机进程环境提供，不写入源码或共享的 IDEA 配置。AI Key 保存于 MySQL 的 `ai_provider_credential` 表，不返回浏览器、不写日志；启动时只在没有既有记录时导入环境变量。`.env.example` 仅列变量说明，Spring Boot 不自动加载 `.env`。`hospital-server/scripts/start-dev.ps1` 是可选启动辅助工具，日常开发可直接运行启动类。

2026-10-14 已用当前代码打包并启动本机服务，前端代理管理员登录、MySQL 和 PostgreSQL 健康检查均通过；AI Key 已保存到本机 MySQL，后端启动时未设置 `DASHSCOPE_API_KEY` 仍读取到数据库配置。重启电脑后需重新启动前后端。
