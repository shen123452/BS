# 医院智能导诊系统

毕业设计题目：**基于检索增强生成与智能体的医院智能导诊系统设计与实现**。

开发依据为[缩减版 V2.2](缩减版/README.md)，采用单机模块化单体架构，网站角色固定为管理员、医生、患者。更新日期：2026-10-13。

## 技术与数据库

| 部分 | 技术与职责 |
|---|---|
| 前端 | Vue 3、Vite、Element Plus、Vue Router、Axios，蓝白管理界面 |
| 后端 | Java 21、Spring Boot 3.5.13、MyBatis-Plus 3.5.15、Spring Security、JWT、LangChain4j 1.0.1 |
| 本地 MySQL 5.7 | `127.0.0.1:3306/hospital_triage`，15 张表，保存账号、门诊业务、问诊、导诊及知识资料正文 |
| Docker PostgreSQL / pgvector | `127.0.0.1:5433/hospital_triage_vector`，保存知识向量，使用独立 JdbcTemplate 与事务管理器 |
| 模型服务 | 阿里云百炼，`qwen-plus`、`text-embedding-v4`，向量维度 1024 |

数据库连接账号与网站三角色分别配置。两个数据库无跨库外键，不使用分布式事务。

## 当前开发成果

- 管理员：用户启停、科室/医生维护、排班管理、知识资料上传/启停/失败重试/检索、三个只读工具说明、导诊运行记录和基础统计。
- 医生：本人排班、名下候诊列表、患者档案、当天开始接诊、七段病历草稿保存及提交。
- 患者：注册登录、个人档案、七日号源查询、预约与取消、就诊与已提交病历、流式 AI 问诊、症状确认、导诊运行与结果、关联预约。
- 导诊 Agent：模型选择固定工具，最多 4 轮、6 次工具调用、总时限 60 秒；支持轮询、取消、引用校验、急症拦截、有限证据降级和过期结果失效。

系统开发进度估计约 75%～80%，为工程估算，不代表最终验收通过。知识库维护重建、会话删除与历史导诊恢复、完整真实模型联调、性能与效果实验、交付材料仍待完成。具体证据见[开发进度](docs/开发进度.md)。

## 本地启动

1. 启动本地 MySQL 5.7 和 Docker 中的 `hospital-triage-pg`。新环境先按[SQL 说明](缩减版/sql/README.md)初始化两个独立数据库；已有本地数据库不要重复建表。
2. 在 IDEA 打开 `hospital-server/pom.xml`，选择 JDK 21。
3. 在 `HospitalApplication` 的本机运行配置填写 `MYSQL_PASSWORD`、`VECTOR_DB_PASSWORD`、`JWT_SECRET`。使用 AI 时再配置 `DASHSCOPE_API_KEY`。变量说明见[后端 README](hospital-server/README.md)。
4. 运行 `com.shen.hospital.HospitalApplication`，默认监听 `http://127.0.0.1:8082`。首次空库须显式配置管理员初始化；本机已有管理员，无需重新创建。
5. 在 `hospital-web` 首次运行 `npm install`，之后运行 `npm run dev`，或使用 IDEA 的 npm `dev` 任务。
6. 打开 **http://127.0.0.1:5173**，使用本机已设置的账号登录。患者可公开注册，医生由管理员创建。

密码和密钥由本机进程环境提供，不写入源码或共享的 IDEA 配置。`.env.example` 仅列变量说明，Spring Boot 不自动加载 `.env`。`hospital-server/scripts/start-dev.ps1` 是可选启动辅助工具，日常开发可直接运行启动类。

2026-10-13 已用当前代码重新打包并启动本机服务，前端访问、管理员登录、MySQL 和 PostgreSQL 健康检查均通过；本次运行未配置 AI Key，普通门诊页面可用，AI 功能暂未启用。重启电脑后需重新启动前后端。
