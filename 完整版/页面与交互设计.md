# 页面与交互设计

本文件基于已审阅的 11 张原型图，使用用户指定 ui-ux-pro-max 的通用规则制定 Vue 3 + Element Plus 设计规格。原型截图是功能和布局参考；本文是拟实施的优化方案，不代表页面已开发。

## 1. 设计方向

界面采用清晰、平静的医疗服务风格：白色工作区、浅灰蓝背景、较深蓝色主操作、青绿色辅助识别。把风险提示、就诊日期、下一步操作和内容可读性置于装饰之上。

患者端强调引导和解释；医生端强调快速录入与避免误操作；管理端强调筛选、批量处理和可核实的数据。共用颜色、字体、间距、状态词和组件，避免三套完全不同的界面。

### 1.1 颜色与字体 Token

| Token | 建议值 | 用途 |
|---|---|---|
| --color-primary | #1D4ED8 | 主按钮、当前导航、主要链接；白色按钮文字 |
| --color-primary-soft | #EFF6FF | 推荐信息与选中背景，配深蓝文字 |
| --color-accent | #0F766E | 完成步骤、知识来源等辅助强调 |
| --color-text | #0F172A | 标题和主要正文 |
| --color-text-secondary | #475569 | 次级说明、表头，不用过浅灰色 |
| --color-surface | #FFFFFF | 内容卡片与表单 |
| --color-background | #F5F7FB | 页面底色 |
| --color-border | #D7DFEA | 一般分隔线；输入框必要边界另做高对比校验 |
| --color-success | #15803D | 成功文字与标识，同时显示“已完成” |
| --color-warning | #92400E | 注意/需补充信息，配浅暖色背景 |
| --color-danger | #B91C1C | 危急、错误、破坏性操作，配明确文字和图标 |
| --radius-control / --radius-card | 8px / 12px | 控件与卡片圆角 |
| --shadow-card | 0 2px 12px rgba(15,23,42,.06) | 只用于需要分层的区域 |

中文字体：`"PingFang SC", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`。系统字体优先，避免为装饰加载多组在线字体。数字启用 tabular-nums。

字号：页面标题 24–28px；模块标题 18–20px；患者正文 16px、行高 1.6；桌面管理正文 14px、表格 13–14px；辅助信息 12–13px。手机输入框与正文至少 16px。危险说明不能缩成灰色小字。

采用 4/8px 间距尺度：4、8、12、16、24、32、48。默认卡片内边距 20–24px，手机 16px。主操作 44px 高，图标按钮提供至少 44×44px 点击区域。

Element Plus 主题覆盖使用 Token，例如 `--el-color-primary`；同时定义 hover/active/focus/disabled 色，不只改默认蓝色。正常文字对比度 ≥4.5:1，必要非文字控件边界与图标 ≥3:1，实际实现时逐项测量。

### 1.2 布局

- 患者桌面端：顶部 64px 导航；内容最大宽度 1,200px；左右至少 24px 留白。
- 患者手机端：底部四项导航“首页、问诊、挂号、我的”；个人档案和就诊记录放“我的”。聊天详情不同时叠加底部导航和高输入区。
- 医生/管理员桌面端：220px 侧栏、64px 顶栏、主区 24px 留白；支持侧栏折叠。
- 断点：375、768、1024、1440px；患者内容优先堆叠，管理表格在自身容器横向滚动。
- 长病历以页面阅读为主，避免多层弹窗和内外滚动竞争。
- 动画只帮助状态变化，默认 150–250ms；尊重 prefers-reduced-motion。

## 3. 原型逐页优化

### U01 登录 / U02 注册

参考：[1.png](../原型图/1.png)。

保留集中登录卡片，减弱大面积高饱和渐变。桌面可用左侧简洁说明、右侧表单；手机单列表单。

- 输入可见标签“账号”“密码”，placeholder 只举例。
- 密码显隐按钮有 aria-label；Enter 登录；提交时按钮显示“正在登录”。
- 错误就近显示，不清空账号；登录失败不透露账号是否存在。
- 注册只提供患者角色，医生由管理员开通；注册成功跳转档案补全或首页。
- 登录后回到原请求页面，但只能跳同源且符合当前角色的路由。
- 测试账号仅在演示模式显示，不出现生产账号或真实凭据。

验收：手机 375px 可完整操作；Tab 顺序正确；错误后焦点到问题字段；重复点击只发一次登录请求。

### U03 患者首页

参考：[2.png](../原型图/2.png)。

首屏分三块：简短问候与“开始智能问诊”、最近预约/待补信息、快捷服务。原型的蓝色横幅缩短，流程图下移到首次使用提示。

- 有 WAITING 预约优先显示日期、时段、医生、科室、位置与“查看就诊”。
- 无预约时显示“描述症状，获取科室建议”；普通预约入口仍可独立使用。
- 未完善过敏/慢病信息显示轻量待办，不阻断整站浏览。
- 快捷入口为问诊、挂号、我的就诊、医疗档案；不在首屏重复四个同等主按钮。
- 首页不放复杂运营统计，不展示具有诊断意味的健康分数。

### U04 预问诊会话与聊天

参考：[3.png](../原型图/3.png)。

桌面左侧 260px 会话列表，右侧聊天主区；手机历史列表作为单独页或抽屉。会话标题从首条症状生成短摘要，避免全部叫“张三”。

聊天区域从上到下：标题与状态 → 可折叠症状摘要 → 消息列表 → 当前操作提示 → 输入区。分诊结果不固定占据顶部大半屏，生成后跳结果页或给结果卡。

- 用户发送后立即显示自己的消息，助手状态“正在整理”，首段到达后更新正文。
- 发送中主按钮变为“停止生成”；同一会话输入可暂存但不可并行发送。
- Enter 发送、Shift+Enter 换行；尊重中文输入法 composition 状态，避免输入候选词时误发送。
- 用户滚动查看历史后不强制跳底，显示“有新回复”；点击才回到最新。
- 每轮最多 2–3 个补问，支持按问题列表阅读；患者可用自然语言一起回答。
- 达到摘要确认条件时出现“核对症状并获取科室建议”，先确认摘要再发起 Agent。
- 已完成分诊的旧会话只读，给“查看结果”和“复制症状重新问诊”，不只放灰色禁用说明。
- 删除历史会话需要明确确认，说明仅删除列表可见会话，不删除关联就诊记录。

状态覆盖：初始欢迎、输入为空、模型未配置、网络中断、模型失败、用户停止、历史加载、会话已关闭。

### U05 摘要确认

新增页面/大抽屉。

展示主诉、持续时间、部位、程度、伴随症状、否认症状、慢病/过敏/用药、尚需补充内容。患者可以改错；保存产生新的确认版本。

未知项显示“尚未提供”，不默认“无”。需重点核实的高风险问题逐项显示回答状态；确定高危时直接进入急诊引导。主操作“确认并获取科室建议”，次操作“返回补充症状”。

### U06 Agent 运行状态

新增页面，可在分诊结果路由等待态内展示。

使用真实事件时间线：“整理已确认信息”“查询知识片段”“核对科室”“查询可预约排班”“验证建议”。这些是实际动作标签，不预先假装每步一定会发生。

- 显示已完成步骤、当前动作和耗时；步骤数量未知时不用假百分比。
- 关闭页面提示任务会继续，可在历史查看；取消是独立按钮。
- 普通患者只看公开摘要，不看数据库 ID、完整 tool JSON、密钥、内部错误或隐藏思维链。
- 超时/失败给已保存症状、重试和普通预约入口；没有有效结果时不能展示假的成功卡。

### U07 分诊结果

基于 3.png 顶部推荐区扩展。

信息顺序：风险与下一步 → 推荐科室 → 推荐依据充分程度 → 简短理由 → 可挂医生/场次 → 可展开知识依据 → 已采集摘要。

- 普通结果主操作“查看可预约场次”，预选真实推荐科室。
- 无号源时显示科室建议和“暂无可预约场次”，可调整日期，不伪造可挂医生。
- “依据充分程度”使用文字和说明，不出现未校准的 88% 诊断概率。
- 证据卡显示文档名、版本、页码或段落、摘录；患者只能查看授权片段，不能访问上传目录。
- 明确 EMERGENCY：顶部高对比红色风险区，主操作为急诊引导；不显示普通预约主按钮。
- 信息不足：列出缺失项，主操作“补充症状”；已有候选仅作有限参考。
- 已使用结果保留原推荐与已关联预约入口；症状变化或过期提示重新问诊。

### U08 预约挂号列表

参考：[4.png](../原型图/4.png)。

筛选区依次为推荐科室标识/全部科室、未来七天日期、医生/时段。手机科室用选择器而非过长横向标签；日期可在有边界的日期控件切换。

医生场次卡信息：姓名/职称 → 科室/日期/时段 → 剩余 X / 总 Y → 费用 → “选择场次”。展示绝对日期和星期，不仅写“明天”。

- 余号为 0 显示“已约满”，停诊显示“停诊”，超过截止显示“已截止”；不可预约有理由。
- 余号条只作辅助，X/Y 文字始终保留。
- AI 推荐来源在筛选区显示“来自本次科室建议”，可清除，不掩盖其他可预约科室。患者选到推荐集合以外的科室时取消本次分诊关联，按普通预约提交。
- 已在同日期时段有有效预约时禁用重复预约并链接已有挂号，但后端仍兜底。
- 点击进入确认页，不一点击立即创建挂号。

### U09 预约确认

新增。

显示患者姓名、科室、医生、就诊日期/时段、位置、费用、取消截止时间。页面加载重新取版本与余号；主操作“确认预约”，提交中禁用。

只提交 scheduleId/version/triageResultId；费用和日期由后端快照。库存变化时显示“号源已更新”并重新确认；不能自动切另一位医生。成功页显示挂号编号和“查看我的就诊”。该项目没有支付时，文案不用“已付款”。

### U10 我的就诊 / U11 病历阅读

参考：[5.png](../原型图/5.png)。

我的就诊分“待就诊、接诊中、已完成、已取消/未到诊”，列表显示日期、科室、医生、状态和恰当操作；手机使用卡片，桌面可用紧凑表格。

- 待就诊：查看详情、截止前取消；接诊中：查看状态，不取消。
- 已完成且病历提交：查看电子病历；草稿不显示给患者。
- 详情页按时间展示预约、开始接诊、病历提交、完成时间。
- 病历页顶部为患者和就诊概要，正文七段清晰分节；桌面可有右侧段落导航，手机顺序阅读。
- 提交医生与时间明确；正文只读。打印仅打印当前病历授权内容，不连带后台数据。
- 长文本不用小弹窗嵌套滚动；需要弹窗时使用宽抽屉并支持打开完整页。

### U12 医疗档案

新增。

分基本信息、慢病与病史、过敏、正在用药、可选紧急联系人。每个字段有可见标签；未知/无/具体内容通过明确选项表达。过敏史提示填写药物或物质名称，不靠 placeholder 承担说明。

年龄与出生日期输入模式互斥，防止矛盾；保存后显示更新时间。返回/关闭时有未保存提示。病史字段限制长度并说明仅用于导诊和医生查看。

## 4. 医生端新页面

### U13 医生工作台

原型目录没有医生工作台截图，按业务新增。

顶部选择就诊日期；显示待接诊、接诊中、已完成三个数字。主体优先待接诊队列，再显示正在编辑的病历草稿。

患者行显示姓名、年龄、预约时段、主诉摘要、风险提示、当前状态。主操作“开始接诊”只对 WAITING；已有接诊显示“继续接诊”。不按未验证 AI 置信度排序患者。

### U14 接诊详情

顶部身份与预约核对；左侧病史/过敏/用药、确认症状摘要、既往就诊；右侧病历入口与状态。AI 摘要标明来源和时间，医生可以纠正后在病历中记录，不能直接把模型文本作为已签名病历提交。

只加载当前医生授权患者；切换患者时清理上一患者上下文，避免串档。危急风险提示持续可见，不仅在瞬时 toast 中出现。

### U15 七段病历编辑器

使用七个固定分节，桌面左侧段落导航、右侧编辑区；顶部患者身份保持可见，底部固定“保存草稿”和“预览并提交”。

- 自动保存显示“正在保存/已保存于 HH:mm/保存失败”，失败保留当前输入并允许重试。
- 两窗口同时编辑发生 version 冲突时停止自动覆盖，给重新载入与复制当前草稿选项。
- 必填项缺失就近提示；聚焦首个问题字段。
- 提交预览展示完整七段与身份，确认后正文锁定。
- 已提交状态把输入改成可选中阅读文本，不只是灰色禁用 textarea。
- 完成就诊前显示病历已提交；可选组合按钮“提交病历并完成就诊”，后台使用组合事务。

### U16 分诊反馈

医生完成时提供非强制反馈：“科室建议合适 / 应调整 / 无法判断”。调整时可选科室与填写原因。反馈不改变患者既有预约，不把模型意见写成医生诊断。用于评测时展示反馈覆盖率。

## 5. 管理端逐页设计

### U17 管理工作台

参考：[6.png](../原型图/6.png)。

首屏展示今日预约/待接诊、AI 异常数量、知识任务失败、未来七天无号源告警。下方“待处理”列表可进入配置、任务或排班。原型的功能导览作为帮助区折叠，不占据主要工作区。

### U18 排班管理与顺延预览

参考：[7.png](../原型图/7.png)。

保留筛选表格，列为医生、科室、日期/时段、总数、余号、已占用、费用、状态、操作。主要操作为“新增排班”，批量操作折叠到选中后工具栏。

- 行操作使用带文字的编辑、停诊/归档；删除不放在默认主操作附近。
- 有预约行标“已有预约，日期锁定”；修改总量解释余号会按占用重算。
- 日期顺延首先选择“生成未来排班”或“平移无预约演示数据”。
- 预览列出旧日期→新日期、数量、冲突和将跳过场次；已关联预约明确显示保护状态。
- 执行成功显示新增/跳过/失败数量与明细；冲突不能静默覆盖。
- 停诊单独显示受影响 WAITING 预约，操作原因必填，批量取消有确认。

### U19 用户/科室/医生/症状管理

沿用统一表格模板，但按业务定制：

- 用户：账号、角色、状态、最近登录；禁用提示会话撤销。
- 医生：科室、职称、擅长；创建时是否开通账号，密码一次性设置后不回显。
- 科室：编码、说明、位置、急诊标识；停用前显示未来场次影响。
- 症状：同义词、需确认问题、科室权重、可能危急标识；显式说明“停用标签不关闭强制安全检查”。

### U20 AI 模型配置

新增。分“聊天模型”“向量模型”两栏或 Tab，不能混在同一个表单里误用 Key/模型。

字段分为连接参数、能力/生成参数、高级选项。密钥展示“已配置”掩码；修改密钥单独进入输入态，不把掩码写回。

- 保存草稿 → 测试 → 启用为默认；每步有状态。
- 聊天测试分普通、SSE、tools；向量测试返回实际维度和可用 usage。
- 测试用固定无患者信息短样本，说明会发起真实调用。
- 启用说明“下一次新请求生效，正在运行的任务沿用开始时版本”。
- 向量模型变更提示先重建再发布，显示目前服务索引与目标索引，不把保存按钮当作索引完成。

### U21 Prompt 模板

左侧模板分类，右侧草稿、变量列表、输出 Schema 与版本历史。保存草稿和发布是不同按钮；发布填写变更说明，回滚展示目标版本和影响的新请求范围。

预览使用合成样例，提示缺失变量。历史修订只读；对比聚焦模板变化，不显示任何密钥。

### U22 知识库与入库任务

新增，与 8.png 检索页联动。

知识库页显示已发布版本、片段数、目标模型空间；文档列表展示来源、版本、审核、解析/向量状态。上传后进入任务详情，进度按实际处理片段计算。

失败说明区分文件无文本、解析失败、向量 API 失败、维度不符；“重试失败项”不盲目重做全部成功项。发布前显示总片段/成功/失败、空间与维度完整性检查。

切片详情左右布局：片段列表、正文与定位；允许查看原始文本，不允许就地修改已发布片段。修改文档应创建新版本并重建。

### U23 向量检索调试

参考：[8.png](../原型图/8.png)。

上方输入 query、知识库和 TopK；结果显示排名、原始余弦分数、片段摘录、来源位置、spaceKey/indexVersion 与检索耗时。下方索引列表为管理辅助，不用一长张“READY”表替代真实检索结果。

查询无命中显示“当前阈值下没有可用知识依据”；无索引显示重建入口；不得假填 0 分或虚构来源。向量重新生成使用任务入口并给预估片段数量。

### U24 工具中心与测试

参考：[11.png](../原型图/11.png)。

工具列表显示编码、用途、执行器、Schema、状态、修订、超时。顶部“下一次运行可用工具”从后端真实状态读取，开关成功后刷新。

- 开关处理中禁用并显示反馈；失败回滚视觉状态。
- 新增工具只能选择已实现执行器，Schema 编辑有验证和示例。
- 已产生日志工具不物理删除，改停用/归档；历史保留编码和修订快照。
- “测试工具”进入抽屉，使用授权合成患者，显示脱敏请求、响应、耗时与日志链接。
- 帮助文案写清本地工具注册能力，不宣称已经连接远程 MCP server。

### U25 运营看板

参考：[9.png](../原型图/9.png)。

顶栏筛选日期、业务时间口径；每个指标有分子/分母或说明。核心指标为挂号量、完成量、号源使用率、首次转化率、净转化率、反馈一致率。

趋势图采用折线/柱状图，科室比较用横向条形图，转化链可用清晰的数字流程；不用过多圆环。保留科室/医生/推荐科室三 Tab。表格展示样本量与观察中的结果数量。

图表提供数据表替代、悬停/焦点数值、单位和日期；点击指标进入保留筛选的明细。分母为零显示“暂无样本”。不要沿用“命中率=挂号比例”的误导名称。

### U26 AI 调用观测

参考：[10.png](../原型图/10.png)。

KPI：已终结调用、成功率、失败/超时、可用 Token、usage 缺失率、首字 P95/全程 P95。用途汇总点击联动明细。

Token 空值显示“供应商未返回”，不是 0。耗时单位统一：小于 1 秒显示 ms，否则 s；统计同时标样本量。细节抽屉显示 traceId、用途、配置修订、步骤链接和中文错误；敏感请求原文默认不展示。

### U27 Agent 运行详情

新增。运行头部显示状态、摘要版本、模型/Prompt 修订、工具快照、知识版本、预算、起止时间。左侧时间线，右侧选中步骤详情，底部最终校验结果。

使用 MODEL/TOOL/SAFETY/VALIDATION 类型区分事件；显示实际调用/耗时/引用，不放“完整思考过程”按钮。管理员能从失败步骤跳到工具或 AI 日志；患者只看公开动作。

## 6. 通用组件与文案

| 组件 | 行为规范 |
|---|---|
| RiskBanner | 文字+图标+语义色；危急提示不会自动消失；提供明确行动 |
| StatusBadge | 使用统一状态词；颜色只是辅助 |
| EvidenceCard | 文档、版本、真实位置、摘录；加载/无权限状态完整 |
| StreamMessage | 支持生成/中断/取消；纯文本或安全 Markdown；无不受控 HTML |
| AgentTimeline | 实际事件序号与耗时；分公开/管理视图 |
| DraftIndicator | 保存时间、失败重试、版本冲突，避免“保存成功”误报 |
| AsyncActionButton | 防重复、loading、成功/失败、状态恢复 |
| FilterBar | Enter 查询、重置、查询条件可保留；多筛选渐进展开 |
| EmptyState | 原因+可执行入口；无数据、无权限、请求失败分别处理 |
| ErrorPanel | 中文原因+下一步+traceId 可复制；不用技术堆栈挡住患者 |

推荐文案：“获取科室建议”“推荐依据”“暂无可预约场次”“已保存草稿”“回复中断，可重新尝试”。避免“AI 确诊”“准确率 88%”“永远安全”“已付款”等与实际能力不符的文字。

长任务不要用持续 toast 表达；状态持久显示在任务卡/详情。表单错误放字段下；成功 toast 简短 3–5 秒，危急/提交确认使用持续区块或确认界面。

## 7. 无障碍、响应式与体验验收

- 使用可见 label、语义 button/link、aria-label；不移除默认焦点轮廓。
- 对话流式增量不逐 Token 触发屏幕阅读器，使用单独 aria-live 状态通知阶段/完成。
- 路由切换将焦点放到主标题；弹窗焦点留在弹窗内，关闭后返回触发按钮。
- 颜色同时配文字/图标；图表提供表格和摘要，tooltip 可键盘到达。
- 患者 375px/768px/1440px 验证，200% 缩放、横屏和 reduced-motion 下仍可完成核心流程。
- 表格只在自身容器滚动，固定栏和操作不盖住内容；手机不强行把医生排班塞四列。
- 聊天输入区适应软键盘与安全区；导航/固定操作条预留底部空间。
- 列表加载用稳定骨架；错误不冒充空列表；恢复后保留用户筛选。
- 图标统一使用 Element Plus Icons 或同一 SVG 图标库，不用 emoji 充当导航/风险结构图标。
- 工程实现后实测文字与控件对比度；本文只给 Token 建议，不声称页面已完成无障碍测试。
