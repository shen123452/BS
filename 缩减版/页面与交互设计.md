# 页面与交互设计 · 毕设 V2

版本：V2.2 · 2026-10-11。知识页面遵循MySQL元数据、PostgreSQL/pgvector向量的双库设计。

题目：基于检索增强生成与智能体的医院智能导诊系统设计与实现。按主开发文档的功能和 [数据库与接口](数据库与接口设计.md) 的契约设计，不沿用旧 V1 的普通聊天/关键词方案。

本文件参考此前逐张审阅的本地11张图，明确保留、缩减和新增页面。只有设计规格，尚未实现或运行页面测试。

知识文档进度以MySQL任务状态为准，跨库向量校验全部完成后才显示“可用”；部分向量写入成功不显示完成。检索测试展示实际命中片段、来源、score与耗时；向量库不可用时显示“知识检索暂不可用”和重试入口，基础门诊保持可用。患者流程不展示数据库连接或内部SQL，管理员错误详情仅显示脱敏错误及任务重试提示。

## 1. 设计基线

蓝白医疗服务风格，优先症状、风险、就诊时间和下一步操作。患者界面说明充分，医生界面录入快捷，管理界面筛选与错误易定位。使用 Element Plus 现成组件，统一 SVG 图标，避免装饰性大动效。

## 3. 患者页面详细规格

### P01 登录与注册

参考 [1.png](../原型图/1.png)。保留居中表单，减少背景饱和度。账号/密码可见标签，显隐按钮有aria-label；Enter提交，loading防重复。

患者注册只允许PATIENT，医生/管理员无公开角色选择。失败保留账号输入、不泄露密码。登录后根据角色和同源returnTo跳转；禁用/过期回登录并清旧数据。退出客户端清Token，此版不声称服务端撤销单次JWT。

### P02 首页

参考 [2.png](../原型图/2.png)。首屏短问候+“开始智能问诊”，旁边最近预约或档案待办。保留问诊/挂号/就诊/档案四入口。

有WAITING预约先显示日期、时段、医生、科室；无预约给导诊或普通挂号入口。不要重复四个等权主按钮。手机导航可“首页/问诊/挂号/我的”，档案和就诊在我的中。

### P03 个人档案

新增简单表单：姓名、性别、年龄、慢病、过敏。年龄0–120，UNKNOWN/NONE/KNOWN明确选项；内容空白不自动转NONE。KNOWN需要说明。

保存显示反馈、失败保留输入；离开未保存提示。发起导诊需要必要信息，缺失给表单跳转；普通浏览不强制补完整病史。

### P04 历史会话与SSE对话

参考 [3.png](../原型图/3.png)。桌面左约260px会话列表，右聊天；手机历史独立列表/抽屉。标题从首症状生成短文本，避免全部同名。

1. 发消息立即显示本人消息与助手占位。
2. 真实delta到达才更新正文；等待显示“正在回复”。
3. 生成时发送按钮变“停止”，前端Abort同时调用取消API。
4. 同会话活动CHAT/TRIAGE期间禁用第二次生成，输入可暂存。
5. 用户滚动到历史时不强制滚底，显示“有新回复”按钮。
6. Enter发送、Shift+Enter换行，输入法composition期间不误发送。
7. 流中断保留部分文字、标“回复中断”，GET终态恢复；不偷偷重复付费调用。
8. 相同clientMessageId返回已有状态，前端按messageId查询，不产生重复用户消息。
9. 每轮最多2–3个问题，模型输出按纯文本安全显示。
10. 点击“核对症状并开始导诊”进入P05。

历史删除有确认；活动中409提示先结束生成。逻辑删除不删除关联预约和病历。新消息使旧推荐失效，页面提示“症状已更新，请重新确认并导诊”，历史结果仍在会话详情可查。

状态：空会话、历史加载、模型未配置、生成、已完成、停止、超时、断线、会话忙碌。失败不是空白气泡。

### P05 摘要确认

新增。首版患者核对/填写主诉、持续时间、程度、伴随、否认、慢病/过敏与明确风险问题。自动总结是选做，界面不能假装已由模型正确抽取。

未知显示“未提供”，不默认否认。高风险答案YES/NO/UNKNOWN，来源/说明由规则提供；明确YES给急诊行动，UNKNOWN提示补问或人工咨询。

保存携带expectedSummaryVersion；409保留本地内容并说明服务端已更新。主操作“确认并开始导诊”，其后POST run；生成中不能修改摘要。取消返回聊天保留草稿。

### P06 导诊执行与结果

基于 [3.png](../原型图/3.png) 顶部推荐扩展。创建202拿runId，每2秒轮询实际步骤；进度是“运行中/已完成步骤”而不是虚假百分比。离开页面后台继续，重开相同run不触发新调用。

公开时间线显示实际查询知识/科室/排班等label、状态与耗时，模型可能跳过或重复某种工具，不能预先画成必经固定链。可取消；取消后不显示成功结果。失败给“已保存信息、重试或普通预约”。

结果顺序：
- 风险及下一步提示。
- 已验证科室、简短理由。
- 真实可挂医生/场次入口。
- 知识来源卡：标题、版本、页码/段落、摘录。
- 症状摘要、创建时间与失效说明。

VALID普通结果主操作“查看可预约场次”；无号源保留科室+说明。LIMITED/NEED_MORE_INFO显示缺失项，主操作补充信息/人工咨询。EMERGENCY持续高对比提示，建议尽快急诊、严重时120；普通预约主按钮隐藏。

不显示模型自报88%置信度，检索分数不是诊断概率。患者只读公开步骤，完整tool JSON/Prompt/内部错误属于管理排障。过期或新症状使结果不再作为预约关联入口。

### P07 场次列表与确认

参考 [4.png](../原型图/4.png)。筛选真实科室、七天日期、医生；从结果进入显示推荐来源，可清除。选不同科室清triageResultId，后端仍检查。

卡片：医生/职称、科室、绝对日期+星期、AM/PM、余号X/Y、费用、“选择场次”。已满/关闭/截止给文本原因，进度条只辅助。

确认弹窗/页面重新GET schedule，核对患者、医生、日期、时段、费用、取消截止。提交只含scheduleId/clientRequestId/可选result/症状说明，不能靠前端fee创建记录。一次确认复用请求号直到结果明确，409刷新重确认，不自动换医生。

成功显示挂号号与查看就诊。没有支付，不写“付款成功”。重复时段预约跳已有记录。取消已完成后重约使用新clientRequestId，旧请求号只能返回旧单。

### P08 我的就诊与详情

参考 [5.png](../原型图/5.png) 背景列表。状态WAITING/IN_PROGRESS/COMPLETED/CANCELLED映射中文。手机卡片/桌面表格。

WAITING截止前可取消，确认原因，失败保留当前列表；接诊中只看状态；COMPLETED才进入提交病历。详情显示预约快照、症状、开始/完成/取消时间。显示历史快照，不随当前医生改名/排班变化。

### P09 病历阅读

参考 [5.png](../原型图/5.png)。七段清楚分节，标题患者与医生、科室、日期、提交时间；长病历用详情页或宽抽屉，避免小弹窗多重滚动。

SUBMITTED只读但可选中文字；草稿不存在于患者API视图。打印选做，范围只有当前授权病历。无提交正文给“尚未提交”，不显示医生草稿文本。

## 4. 医生页面

### P10 工作台与接诊

原图没有医生专门页面，按功能新增。日期与状态筛选、待接诊/接诊中/已完成数字、自己的预约队列。每行姓名、年龄、时段、主诉、状态；开始接诊后进入详情，已开始用“继续接诊”。

接诊详情显示档案、过敏/慢病UNKNOWN明确、挂号症状与关联导诊信息时间。AI说明是参考，不能自动当成医生签署结论。切换患者清前一个上下文，始终显示当前身份。

### P11 七段病历编辑

左段落导航+右表单，手机自然顺序。顶部固定患者/预约身份，底部“保存草稿”“预览并提交完成”。

本版手动保存，清楚显示未保存/已保存时间。离开有未保存确认。保存带version，冲突停止覆盖，允许复制当前内容再重新载入。

七段有可见label和长度提示。未查项目填写说明，提交前预览身份和正文，确认后后台原子提交病历+完成挂号。失败不能清空表单或显示成功。提交后切为只读文本，不仅灰色textarea。

### P12 本人排班

复用 [7.png](../原型图/7.png) 表格结构，医生只读，无编辑总量/余号/关闭按钮。日期、时段、科室、已占用、状态。显示已关闭原因（若后续增加字段），当前基线只显示状态。

## 5. 管理页面

### P13 首页与统计

参考 [6.png](../原型图/6.png)、[9.png](../原型图/9.png)。KPI患者数、医生数、今日新挂号(createdAt)、今日完成(completedAt)。下方日期窗挂号趋势与科室分布，标是否包含取消。

失败文档任务/超时运行提供跳转。原型大欢迎横幅缩短，功能介绍折叠。无需医学命中率、复杂转化或医生绩效图表。

图表可切表格，轴标日期/单位，有数值tooltip和无数据提示。分母为0不虚构百分比，管理统计以少量种子可手算。

### P14 用户、科室、医生管理

统一FilterBar+表格+增改弹窗：
- 用户：角色、状态，禁用确认影响旧Token，密码不回显。
- 科室：编码唯一、名称、职责、位置、急诊标识，停用前检查关联影响。
- 医生：账号绑定、科室、职称、擅长，创建时可开户；有预约转科拒绝并给说明。

不加全院患者病史浏览、病历编辑或症状标签治理菜单。通用CRUD不能绕过业务限制。

### P15 排班

参考 [7.png](../原型图/7.png)。筛选科室/医生/日期/status；行列为总号源、余号、已占用、费用、状态与编辑/关闭。

有历史预约时日期/医生/时段只读，编辑总量显示“余号按占用重算”；总量低于占用拒绝。有WAITING/IN_PROGRESS关闭给409与处理说明，无批量静默取消。新增未来场次，移除“顺延并重置”按钮。

### P16 知识文档与任务

新增上传页，与 [8.png](../原型图/8.png) 联动。上传TXT/PDF、标题、来源、版本；提示10MB/100页、文本PDF支持、扫描件暂不支持。

202后显示documentId，轮询实际状态QUEUED/PARSING/CHUNKING/EMBEDDING/READY/FAILED。解析阶段未知片段总数用阶段标签，Embedding有completed/total后才显示百分比。

失败区分无文本、解析、AI凭据/额度、维度、超时，给“重试失败项”，成功项不重复插。READY可启停；任务活动或全量维护中禁用修改并说明。

全局知识状态AVAILABLE/MAINTENANCE/UNAVAILABLE持续横幅。重建确认说明暂停新RAG导诊，既有任务需结束/取消；普通预约不受此功能限制。重建失败不显示可用，列失败文档；完成全部空间一致才恢复。没有热切换页面。

### P17 片段与向量检索测试

参考 [8.png](../原型图/8.png)。输入query、TopK；返回排名、原始score、来源、页码/段落、excerpt、当前spaceKey和耗时。无命中说明，不能补虚构来源。

文档片段页正文/定位/维度/状态，已发布文本只读；改资料上传新版本。管理员score显示为余弦相似度，不叫正确率。患者引用仅摘录，无原文件公开URL。

### P18 固定工具说明与运行详情

参考 [11.png](../原型图/11.png) 和新增详情。工具页只展示三编码、说明、入参Schema与只读属性；无注册/删除/启停按钮，不标远程MCP已接入。

运行列表按时间/status筛，详情显示input症状摘要脱敏、模型名/指纹、Prompt哈希、摘要版本、预算、实际round/tool数、终态。时间线选择步骤看输入摘要/真实输出/引用/错误。

步骤类型MODEL/TOOL/SAFETY/VALIDATION/FINAL；不能显示“完整思考过程”。调用logs链接用run/step关联。内部原文默认不展示患者完整病史或Key，排障数据裁剪。

### P19 AI调用日志

参考 [10.png](../原型图/10.png)。简化表格：用途、模型、起止、耗时、状态、Token、错误。用途PRECONSULT/AGENT/EMBED_DOCUMENT/EMBED_QUERY，与数据库一致。

Token为空写“供应商未返回”，不显示0消耗。详情有trace和run/message/document链接、中文错误。没有成本价格管理或多维统计平台。真实每轮调用有独立记录，列表不会把一个run只算一次。

## 6. 组件、状态与文案

| 组件 | 必须覆盖 |
|---|---|
| StreamMessage | 等待/增量/完成/中断/取消、查终态 |
| SummaryForm | UNKNOWN/NONE区分、版本冲突、确认 |
| AgentTimeline | 实际步骤、轮询、终态停止、取消 |
| EvidenceCard | 标题/版本/定位/摘录、无授权/无引用 |
| ScheduleCard | 剩余/截止/满/关闭、确认 |
| RecordForm | 七段、手动草稿、version冲突、提交只读 |

推荐文案“获取科室建议”“知识参考”“暂无可预约场次”“需要补充信息”“回复已中断”。不用“AI确诊”“准确率88%”“临床已验证”或“已付款”。

长期任务状态放页面，不用消失的toast承载关键错误/风险。成功toast约3–5秒，危急风险持续显示。每页一个主操作，破坏性删除/关闭有确认且与主按钮分离。

## 7. 页面验收

- 375/768/1440宽度，患者核心路径不横向溢出。
- 标签、Tab顺序、可见focus、弹窗焦点返回正确，错误聚焦相关字段。
- aria-live只播阶段/完成，不逐Token轰炸屏幕阅读器。
- 颜色配文字，图表有数据表，200%缩放可用。
- reduced-motion下不丢进度信息。
- CHAT/TRIAGE状态后端409与前端禁用一致，停止/中断有恢复。
- 日期为绝对日期+时段，费用快照和接口一致。
- 错误/无数据不同，未实现扩展不挂空菜单。
- 新页面没有实际截图时标设计，不当作已开发成果。
